# The Neighbours

Aider is one shape of AI help with
code. The neighbours below are
characterised, not run or benchmarked
— the lab's evidence covers Aider
alone — but choosing between them is
mostly choosing a shape, and the
shapes are clear.

**Plain chat, with copy and paste.**
A browser chat window (the providers'
own, or a local one from the Open
WebUI guide in this series) plus your
hands as the transport. No install, no
integration, any model you can open.
It is also the workflow chapter 1
described: you are the edit format,
the repo map and the commit message,
and on a multi-file change you will
feel each of those jobs. Aider exists
because that stops scaling.

**The editor assistants.** Cursor,
Windsurf, Continue, GitHub Copilot and
their kin live inside the editor: the
code is already on screen, suggestions
arrive as you type, and a chat pane
shares the window. If your work is
writing new code at the keyboard,
that closeness is worth a great deal.
Aider's counter-offer is the terminal
and the repository: no editor to
adopt, the whole session in git, and
any model — including a local one the
editor tools will not talk to. Many
programmers run both, the editor for
typing and Aider for tasks.

**The other terminal agents.** Claude
Code and OpenAI's Codex CLI are the
closest kin: terminal-first, file-
editing, model-backed. The differences
are of gravity, not kind. They are
each bound to one provider's models
and accounts, with the polish that
focus brings; Aider is provider-
neutral — hundreds of models through
LiteLLM, local ones included — and
counts its git discipline (a commit
per change, the map, the edit formats)
as its home ground. If you already pay
one provider and want its agent, the
choice makes itself; if you want the
model to be *your* choice, it makes
itself the other way.

**The hosted agents.** Web services
that take a whole task — an issue, a
feature description — and return a
pull request, working on their own
machines in their own time. A
different bargain entirely: delegation
instead of pairing. Aider never leaves
your terminal or your supervision;
the hosted agents never enter them.
For a solo maintainer the question is
usually which jobs deserve which
bargain, not which tool wins.

**Doing it entirely locally.** Pair
Aider with Ollama (chapter 4) and the
neighbourhood changes meaning: the
"competition" becomes a chat window on
the same local model, and the choice
is purely about workflow. It is also
the only arrangement in this chapter
where the code, the questions and the
answers never leave one machine — for
some projects that settles it before
features are compared.
